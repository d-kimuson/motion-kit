# core

The master clock. core defines the Composition, the timeline it runs on, how Sequences and Transitions place scenes in time, and the Time Module that converts between frames and time. It is not responsible for how anything looks.

## Invariants

- Within the supported A/B paths and a fixed environment, a frame is a pure function of its Presentation Time: rendering frame N gives the same output whatever frame was rendered before. Tier C remains usable, not covered by this guarantee; in Phase 1 the Browser Renderer emits `seek.uncontrolled` when an integration is identified as Tier C.
- A Sequence contains time `t` exactly when `start <= t < end` (`Sequence.membership`, `Sequence.start_included`, `Sequence.end_excluded`). Intervals whose endpoints meet, `[a, b)` and `[b, c)`, share no time (`Sequence.adjacent_disjoint`); this does not prohibit overlapping TransitionSeries scenes. Zero-length Sequences are empty (`Sequence.zero_length`). `createSequence` accepts signed starts and nonnegative durations. Local time is the signed exact difference from the start, even outside membership; nested offsets compose without rounding (`Sequence.local_time_zero`, `Sequence.local_time_composition`).
- Frame boundaries are not rounded to integers before the Time Module converts them; fps may be rational (30000/1001). `createTimelineTime` accepts exact `{ numerator, denominator }` input with safe integer components and positive denominator, or finite number seconds within the safe numeric range. Number seconds mean the decimal printed by `String(value)`, not the underlying binary fraction; use rational input when exactness is required. Internally, normalized bigint components preserve arbitrarily large intermediate products. `toSeconds` is a lossy expression-library boundary (including numeric overflow/underflow), never a comparison or rounding input.
- Signed mathematical conversions are unrestricted: `frameToTime(n, fps) = n / fps`, and `framePosition(t, fps) = t * fps`. `timeToFrameFloor` is the default presentation-time-to-frame conversion; an exact frame boundary belongs to that frame. It is monotonic for positive fps and round-trips every signed frame (`Timeline.floor_monotonic`, `Timeline.frame_roundtrip`, `Timeline.floor_bounds`). `timeToFrameCeil` and `timeToFrameNearest` are explicit helpers only; nearest breaks half-frame ties toward positive infinity, including negative ties (`Timeline.ceil_bounds`, `Timeline.nearest_bounds`, `Timeline.nearest_tie`).
- `frameCount(duration, fps)` accepts nonnegative durations and returns `ceil(duration * fps)`; `durationFromFrameCount(count, fps)` reports the exact inverse `count / fps`. That reported duration can exceed the originally requested duration, but counting it returns the same count (`Timeline.frame_count_roundtrip`). Zero duration has zero frames (`Timeline.frame_count_zero`). The last sample is before the requested end; the next sample is at or after it (`Timeline.sampling_bounds`).
- `validateOutputFrame(frame, total)` validates output requests separately from signed mathematical conversion: a safe integer number in `[0, total)` returns `Result<bigint>` success; invalid, negative or out-of-range requests return an error Diagnostic with code `composition.props-invalid`, never clamp or throw (`Timeline.last_frame`, `Timeline.frame_past_end`, `Timeline.negative_frame`). Rejected safe-integer frames appear in `location.frame`; malformed numeric inputs omit location because the Diagnostic schema cannot represent them, and name the received value in the message. Invalid rational/seconds/fps input uses the same code; negative durations/counts and invalid overlap layouts use `composition.duration-invalid` through `Result`.
- `createTransitionSeries` requires exactly one overlap per adjacent scene pair and nonnegative scene durations. Each overlap satisfies `0 <= overlap <= min(left duration, right duration)`; equality is permitted (`Transition.overlap_bounds`). An overlap equal to the outgoing duration starts the incoming scene at zero relative to the outgoing start and leaves the pair with exactly the incoming duration (`Transition.overlap_equal_scene`, `Transition.full_overlap_duration`). At any index and layout offset, incoming scenes start at outgoing end minus overlap (`Transition.layout_adjacent`); both layout-placed scenes are present throughout that half-open overlap (`Transition.layout_overlap_membership`). Zero overlap is empty (`Transition.zero_overlap`). Pairwise constraints do not prohibit multiple simultaneous overlaps in a longer series.
- The total duration of a `TransitionSeries` is the sum of its scenes minus the sum of its overlaps; accumulated placement satisfies this formula (`Transition.placement_total`). Layout entry `i` starts at the initial offset plus the sum of durations before `i` minus the sum of overlaps before `i`, and ends one scene duration later (`Transition.layout_entry`). For durations `[10, 10, 10]`, overlaps `[2, 3]`, and initial offset zero, the placed intervals are `[0, 10)`, `[8, 18)`, `[15, 25)` (`Transition.layout_three_scenes`). An empty series has zero duration and no intervals (`Transition.empty_series`, `Transition.layout_empty`). `sampleTransition` clamps progress before the overlap to 0 and at or after its end to 1 (`Transition.progress_before`, `Transition.progress_after`). Positive overlaps start at 0 (`Transition.progress_start`) and reach 1 at the exclusive end (`Transition.progress_end`). Zero overlaps are never active and switch directly to 1 at their start (`Transition.zero_overlap`, `Transition.progress_end`).
- A component that cannot be identified is never assumed to be Tier A or B.
- The [Composition registry contract](adr/20261024-composition-registry.accepted.md) uses schema-owned defaults, not a parallel `defaultProps`; only validated JSON props mount the selected component. Components and schemas remain in the composition realm. Non-empty component `defaultProps` (class statics, inherited defaults or function properties) and unreadable/accessor defaults are rejected at declaration with `render.page-error`, naming the component and stating that schema defaults are the only defaults authority. Descriptor inspection executes defaults getters zero times across repeated declarations, whether they throw or return empty defaults. Absent, null/undefined or empty data defaults are allowed; inherited enumerable keys inside a defaults object are non-empty. Recursively unwrap `memo` to its inner component and `forwardRef` to its render function, validating defaults on every layer. Reject `lazy` without resolving its payload, including within wrappers: `render.page-error` names the `component` field, explains that validation cannot precede resolution, and hints to lazy-load inside the component instead of the registry entry.
- The [loading design](../render/design-doc/20261024-composition-loading.md) shares core's browser bootstrap and Composition runtime implementation between preview and renderer, never their sessions, host scheduling or mutable Composition realms.
- core's contract provides one Composition runtime implementation for the Browser Renderer and the [browser preview](../preview/CONTEXT.md) to consume. _Amended 2026-11-01 (TASK-246):_ the bootstrap serves a preview host when its shell URL says `?host=preview` (`servePreviewPort`, `src/core/runtime/preview-port.ts`): it installs no `window.__motionKit` and no Playwright callbacks, answers the preview protocol over one transferred `MessagePort` from its parent window, grants ownership in-page, and relies on core's own frame timeout; `createLoadingPage(input, host)` makes a Loading Page serve exactly one host source (`renderer` or `preview`). Presentation Time stays fixed while registered work settles. Completion belongs to the active frame generation and resource versions, not just a frame number; allocating a queued generation does not invalidate the active one. Resource-version changes re-settle within that generation; cancellation or supersession aborts it without publication. The [readiness barrier contract](../../decisions/20261024-time-control-and-frame-capture.accepted.md#readiness-barrier-contract) defines exclusive ownership, queueing and deadlines.

## Public timeline API

Scene authors use `defineComposition`/`defineCompositions`, `Sequence` and the four hooks from the package root. `Composition` is the page-side runtime root, not a scene-author declaration; the browser-only `/browser` bootstrap owns runtime construction. The existing root runtime exports remain available; the bootstrap itself is not re-exported by the root.

| Term             | Code              | Definition                                                                                                      |
| ---------------- | ----------------- | --------------------------------------------------------------------------------------------------------------- |
| Sequence context | `SequenceContext` | Numeric local timing for the nearest Sequence, or the whole Composition when no Sequence encloses the consumer. |
| Timeline context | `TimelineContext` | Composition-scoped numeric timing and exact static metadata, unaffected by enclosing Sequences.                 |

```ts
type SequenceContext = Readonly<{
  time: number;
  duration: number;
  remaining: number;
  progress: number;
  localFramePosition: number;
  fps: number;
  globalTime: number;
  globalFrame: number;
}>;
type TimelineContext = SequenceContext &
  Readonly<{
    id: string;
    width: number;
    height: number;
    durationInFrames: number;
    frameRate: FrameRate;
  }>;

declare function useTime(): number;
declare function useFrame(): number;
declare function useSequence(): SequenceContext;
declare function useTimeline(): TimelineContext;

type SequenceProps = {
  from: number | RationalInput;
  duration: number | RationalInput;
  name?: string;
  children: ReactNode;
};
declare function Sequence(props: SequenceProps): React.JSX.Element | null;
```

- The product owner's numbers-versus-rationals decision is explicit: `time`, `duration`, `remaining` and `globalTime` are seconds as `number`; `progress` is the dimensionless ratio `time / duration` as `number`; frame values are `number`; `fps` is the decimal rate (for example, approximately 29.97002997 for 30000/1001). `useTimeline().frameRate` additionally exposes the exact Time Module `FrameRate`, not the declaration's `RationalInput`. The `FrameRate` has normalized bigint numerator/denominator; `durationInFrames`, width and height retain the validated integer metadata.
- `useTime()` returns local seconds; `useFrame()` always returns the global output frame. `useSequence()` reports the nearest declared interval's local time, duration, remaining time and progress, fractional `localFramePosition`, decimal fps, global seconds and global frame. `useTimeline()` reports those same fields relative to the whole Composition: `time` and `globalTime` are the current Presentation Time in seconds, `localFramePosition` is the global frame position, and duration derives only from `durationInFrames` and exact fps. Using any of the four hooks outside the Composition runtime is a programmer error: it throws an `Error` with the exact message `useCompositionFrame requires a Composition provider.` Nothing renders; there is no silent fallback. This is an exception for a programming mistake, not a returned Diagnostic for invalid props.
- Outside a Sequence but inside Composition, `useTime()` is global seconds and `useSequence()` uses `[0, composition duration)`. This explicit fallback avoids a nullable hook and gives scene authors usable timing at the root. A zero-duration Composition remains inspectable but has no output frame, so its scene and hooks never mount.
- `<Sequence from={2} duration={3}>…</Sequence>` uses seconds, with `from` relative to the enclosing Sequence's start (or zero at the Composition root). Exact rational seconds are also accepted. Global interval endpoints remain exact; only the hook return values undergo lossy number conversion. Neither numeric return values nor previous frames feed timing calculations. No hook or Sequence schedules work or reads an ambient clock.
- Sequence membership is exactly `[start, end)`: children are not rendered outside it, including a zero-length interval at its start. Nested Sequences add offsets exactly, and ancestor membership clips visibility without changing the child's declared duration, local origin or progress. Signed starts and ends beyond the Composition duration are **valid**, matching `createSequence`; only valid output frames can render. Negative duration, nonfinite/out-of-safe-range number seconds or malformed rational input are invalid authored JSX and throw; the existing Composition error boundary reports `render.page-error`. A valid but entirely offscreen interval is simply empty in the output. No extra containment constraint is imposed on the Time Module's signed-interval contract.
- `name` labels a Sequence for hosts (the browser preview timeline draws them since TASK-246, and review comments name them since TASK-245) and never changes rendering. Named ancestors form a Sequence Path, outer to inner; unnamed Sequences add no segment. Each named Sequence registers with its runtime while it is mounted, including while it is itself inactive: it is reported whenever every enclosing Sequence (named or unnamed) and Transition shows the current frame, since an inactive one renders none of its children. `runtime.sequences()` (and the page's `sequences()`) report each as a `SequenceSpan` `{ path, startFrame, endFrame }`: the half-open frames of its interval clipped to its ancestors (`timeToFrameCeil` on both endpoints), not clamped to the Composition duration. A Sequence its ancestors never show has an empty span. Siblings may share a name; spans are ordered by start frame, path (outer first) and end frame, never by registration order. `SequenceSpan` is a package-root type because it is the return type of the public runtime; `activeSequences(spans, frame)`, which selects the spans showing at a frame, is internal to the repository (tested here; the preview host highlights the spans of its frame reply that are showing at the shown frame). An empty name is invalid authored JSX and throws.

`composition/timeline-hooks.browser.test.tsx` imports the public package root in the existing Chromium `composition-dom` project. It asserts every field at 30000/1001 fps, fractional local frame positions, exact start/end boundaries, nested offsets, clipping, zero duration, invalid authoring and missing providers. Sequential values for 90 distinct frames match three seeded random permutations, reverse order and repeated seeks. The tests use the landed runtime's owned Presentation Time, not a second test clock or provider. A snapshot-accessor probe deliberately supplies Presentation Time inconsistent with `globalFrame` to pin the runtime's ownership: hooks consume that time rather than recomputing it from the frame. Fractional-position assertions also compare strictly against the Time Module's final conversion of hand-calculated rationals, so premature numeric conversion fails.

## Transition component API

The package root exports `TransitionSeries`, `TransitionScene`, `Transition`, their props types, and `useTransitionProgress(): number`. No effect presets, style injection or DOM wrappers are included.

```tsx
<TransitionSeries>
  <TransitionScene duration={4}>
    <Intro />
  </TransitionScene>
  <Transition duration={0.5}>
    <OverlapContent />
  </Transition>
  <TransitionScene duration={5}>
    <Product />
  </TransitionScene>
</TransitionSeries>
// Inside OverlapContent: const progress = useTransitionProgress();
```

- `TransitionSeriesProps` has optional `children: ReactNode`. Its direct children must be `TransitionScene` declarations, with at most one `Transition` between adjacent scenes. Arrays and empty React children are supported; fragments, custom declaration wrappers, text and unrelated elements are rejected. An empty series renders nothing. Adjacent scenes without a Transition have a zero overlap (a hard cut).
- `TransitionSceneProps` requires `duration: number | RationalInput` and `children: ReactNode`, and accepts the same optional `name` as `SequenceProps`. `TransitionProps` requires the same duration input and accepts optional children. Duration validation and layout use `createTransitionSeries`; overlap sampling uses `sampleTransition`. Negative durations, malformed rational/number input, invalid overlaps and invalid child order throw as authored JSX errors, reported by Composition as `render.page-error`.
- A series begins at the enclosing Sequence's exact global start (zero at the Composition root). Internal absolute placement translates the pure layout's endpoints exactly once, without converting through numeric hook values or reapplying a relative Sequence offset. Scene children observe their own declared interval through the timeline hooks. Nested Sequences and series use the scene's origin; ancestors clip visibility without changing declared timing.
- Total duration remains **sum(scene durations) − sum(overlap durations)**, as specified in Invariants (`Transition.placement_total`); components do not change Composition metadata. For scene durations `[2, 3, 1]` and overlaps `[0.5, 0.25]`, total duration is `5.25`, and no scene remains mounted at that exclusive end.
- Each scene mounts on `[start, end)`; both neighbors mount throughout their overlap. Each Transition's children mount only on its own half-open overlap and observe that overlap's local interval via `useSequence()`/`useTime()`. `useTransitionProgress()` exposes its exact sampled ratio converted once to a dimensionless `number`, starting at 0. The exclusive end (progress 1) is not rendered. Zero-duration overlaps never mount their children. Simultaneous overlaps have independent progress providers.
- `useTransitionProgress()` without an active Transition throws `useTransitionProgress requires an active Transition.` There is no fallback progress outside an overlap. A standalone TransitionScene is also an authoring error. Scene siblings do not inherit a Transition's progress context; the minimal hook is for Transition descendants, not an effect API.

`composition/transition-series.browser.test.tsx` imports the root API in Chromium and asserts layout and duration, first/last/after-end samples, effect-observed unmounts, fractional starts and rational FPS, full and simultaneous overlaps, nested timing and clipping, zero/empty layouts, invalid authoring, and identical trees under sequential, seeded random, reverse and repeated seeks.

## Composition API and host integration

- `defineComposition` returns `Result<CompositionDefinition<Schema>>`; `defineCompositions` accepts the heterogeneous tuple of these Results and returns `Result<CompositionRegistry>`. An entry exports that result as `compositions`. Branch on `ok` before using the registry; declaration failures do not escape module evaluation as exceptions.
- `defineComposition` also accepts an optional `audio: AudioTrack[]` (`src`, frame-based `startInFrames`/`endInFrames`/`offsetInFrames`, `volume`). The clips are validated at declaration — a track that ends at or before it starts, or a negative frame count, fails with `render.page-error` — and travel as plain frozen data on the descriptor inside `listCompositions()`, so Node reads them without a DOM or RPC channel. Playing, mixing and resolving their paths belong to render ([audio muxing ADR](../render/adr/20261026-audio-track-muxing.accepted.md)); core only carries the declaration, and a Composition that declares none is unchanged.
- `registry.listCompositions()` returns ordered, frozen plain descriptors without mounting or parsing props. `validateDefaults(revision)` caches successful validation of every entry for that revision and shares in-flight checks; failed/expired checks are evicted for retry. `mount({ compositionId, props, revision })` selects exactly one entry, awaits defaults and parses the raw props once, returning a page-local `PreparedComposition`. Its schema and component never cross transport.
- `<Composition definition={prepared} compositionRuntime={runtime} />` supplies only the selected component's validated props. Create its runtime with `createCompositionRuntime({ definition: prepared, compositionRealm, instance })`; `instance` must be fresh for each realm. No user content renders until ownership supplies a snapshot. `useCompositionFrame()` reads that explicit snapshot; nested Composition roots are rejected rather than treated as Sequences.
- Required nested Suspense content uses a `registerContent(id, version)` handle created **outside** the suspending subtree and a `CompositionContent` inside the content branch, never its fallback. Layout-effect acknowledgements capture both generation and version. A stale or disposed handle cannot acknowledge its replacement.
- `settleFrame` returns `ready`, `failed` or `aborted`. A ready lease retains ownership. `validateCapture` and `completeCapture` reject stale/source-mismatched/duplicate claims; changed registrations return `resettle`. Call `resettle(lease)` without requesting a new generation. Only `completeCapture` returning `accepted` permits publication. Preview presentation uses this core completion operation without making a screenshot claim in transport.
- Queue and frame budgets default independently to 30 seconds. The frame timer begins after `acquire` confirms the host grant, never in the queue, and is not reset by readiness or re-settlement. The supervised bootstrap uses `externalDeadline: true`: the host owns frame expiry and current-asset classification rather than racing a second page timer. `acquire` receives an AbortSignal for grant revocation. The host must independently enforce its deadline starting at confirmed grant, including capture RPCs. Local timers cannot interrupt blocked JavaScript/GPU work.
- Integrations may supply `pendingAssets()` for current required acquisition/decode/upload observations. The coordinator reads only live registrations for the owning request; this is TASK-158 cooperation, not an asset discovery API. `warnings()` reports detected Tier C registrations with `seek.uncontrolled`. The internal `useCompositionRuntime` hook lets mounted integration consumers register with their realm; it is not a new package-root export.
- Cancellation immediately invalidates the generation. The coordinator waits for registered integration callbacks and optional host `quiesce` before granting another request. A callback that never finishes poisons reuse; TASK-157 must recycle that realm. Integrations receive fixed-time snapshots and AbortSignals, not renderer/library objects.
- `dispose()` attempts every integration disposer and clears registrations/listeners even if a disposer throws. It returns a `Result<undefined>` with a sanitized `render.page-error` on disposal failure; repeated calls return the same result without running disposers again. Hosts must check this result when tearing down a realm.
- Prepared props hold a rebuilt JSON tree checked through every own data descriptor, including nested own `__proto__` values. The component receives deep-equal checked values with shared nested references; React constructs a new top-level props object, so top-level reference identity is not guaranteed. Top-level own `key`, `ref`, `__self`, `__source` and `__proto__` are rejected with `composition.props-invalid` and a message/hint naming the field because React cannot deliver them faithfully; nested uses remain valid JSON data. Non-index array properties and all non-JSON values, including bigint anywhere, are rejected, not silently dropped. Ordinary and null-prototype objects at the root or nested preserve their data through rebuilding, not their prototype. Validate the JSON-object root before reserved-name checks: null, undefined, array and primitive schema outputs return `composition.props-invalid`, not `render.page-error`.
- Defaults and props each receive a fresh configurable 30-second loading timeout. Schema failure and non-JSON output use `composition.props-invalid`; custom messages/input/params are omitted from sanitized issues. Thrown callbacks/loading expiry and invalid width/height/FPS use `render.page-error`; invalid duration uses `composition.duration-invalid`. Invalid output-frame requests are mapped to `render.page-error` at this runtime boundary, leaving the Time Module's existing standalone mapping unchanged.
- React and ReactDOM are host peers at `^19.0.0`; dev versions remain pinned for tests. The implementation uses React 19-compatible APIs, and the tsconfig requires no narrower runtime range. No React implementation is bundled into this source-distributed package.

`registry.test.ts`, `composition-runtime.test.ts`, and the Chromium `composition.browser.test.tsx` and `timeline-hooks.browser.test.tsx` cover the TASK-154 matrix. Font and image acquisition is the [asset readiness contract](#asset-readiness) below. GPU upload, models and texture phases remain three adapters; they register library-neutral work and do not enter core. The public root, browser subpath and emitted loading entry are checked in `scripts/check-browser-graph.test.ts` using bundled Vite and the production loading resolver.

## Asset readiness

The [production contract](adr/20261024-asset-readiness.accepted.md) implements the [registry strategy](../../decisions/20261023-asset-readiness-registry.accepted.md) for fonts and images. Preview and render call the same `useAsset`. The registry and `whenReady` stay on the page runtime; they are not package-root exports and there is no new subpath.

```ts
type FontAssetDescriptor = {
  kind: 'font';
  id: string;
  family: string;
  source: string;
  weight?: number | string;
  style?: string;
  sceneId?: string;
  text?: string;
};
type ImageAssetDescriptor = {
  kind: 'image';
  id: string;
  source: string;
  sceneId?: string;
};
declare function useAsset(descriptor: FontAssetDescriptor): FontFace;
declare function useAsset(descriptor: ImageAssetDescriptor): HTMLImageElement;
```

- Registration is synchronous and happens before a Suspense throw. An effect inside a suspended subtree is not a registration point. Cache identity is kind plus exact source, and for fonts family, weight and style. The caller `id` is diagnostic identity, not cache identity. Equal sources share one load; a different weight or source does not.
- A successful load is reused by live owners. The last owner releasing aborts that load. A later owner starts a new attempt. `retry` starts a new attempt after failure and does not reuse the failed result. A completion whose attempt was superseded or aborted cannot acknowledge the replacement.
- `whenReady` drains until the active generation's required registrations are stable: it does not snapshot `Promise.all` once. A commit may register more work; the loop waits for that work under the same frame generation and original deadline. An unregistered font or image is not treated as ready. Suspense fallback is not a content acknowledgement and is not a capture gate. _Amended 2026-11-01 (TASK-273):_ the root acknowledges the resource revision of the snapshot it committed, and a frame is ready only once the root committed the latest one: a commit of an earlier revision may still show a fallback in place of an asset that has since loaded. A failed registration does not count against a frame when only owners of an earlier generation that never committed hold it, and a content boundary reports a failure against the generation it rendered: under the Held Frame Change, a render cut off before it committed keeps its registrations until the next frame renders over them.
- Load failure is `asset.load-failed`, including when the deadline has already expired. A deadline with still-pending registrations is `asset.not-ready`, listing every pending registration and `timeoutMs`. `pending()` does not include failed registrations. A failure is not published while a sibling registration is still pending, unless the deadline has already fired. Diagnostics are produced in one place. The reported source contains scheme, host, path and at most a redacted query marker; fragments and URL userinfo are stripped, and loader exception text is discarded. Redaction is idempotent: a marker or `[asset source]` is returned unchanged, so a host deadline probe of `pending()` does not percent-encode the marker. Schema validation does not redact. `location` carries known composition, scene, frame and time; `details.assets` carries id, kind, redacted source and phase. An error-boundary `asset.load-failed` is merged with every failed registration, deduplicated by source and phase, and does not abort settlement while another registration is still pending.
- `settleFrame` awaits that settlement before a ready lease. The host capture path still probes `pendingAssets` and will not publish a frame whose registered assets are pending. Three loaders and GPU phases stay outside core and render.

`registry.test.ts` covers ready, pending, failed, cancellation, retry, source change, stale acknowledgement, redaction and the barrier wait. `use-asset.browser.test.tsx` shows registration before the suspended commit. `asset-readiness.test.ts` delays a font and an image and asserts capture pixels and timing only after both load. `node scripts/mutate-asset-readiness.ts` is the opt-in mutation round.

## Seekability

The [accepted Phase 0 ADR](../../decisions/20261024-time-control-and-frame-capture.accepted.md) defines the clock and readiness contract. These classifications are scoped to [Spike A](../motion/knowledge/spike-a-seekability.md) and [Spike B](../three/knowledge/spike-b-seekability.md), not guarantees for whole libraries. A is stateless value evaluation; B needs the verified adapter and acknowledgement; C has uncontrolled time/history. Unverified means no A/B claim, not a fourth Tier; unknown integrations receive C treatment until qualified.

| Feature / examined use                                                 | Tier                             | Reason and boundary                                                                                                                                                            |
| ---------------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| External MotionValue bound to motion.div x                             | B                                | Absolute value writes, no velocity/history dependence or live animation; await per-frame postRender.                                                                           |
| Numeric motion.div style.x props                                       | B                                | React flushSync leaves queued Motion work; postRender is required.                                                                                                             |
| Paused animate(MotionValue, [0,160]) controls                          | B                                | Explicit keyframes, autoplay disabled, pause and absolute time assignment; play/speed/repeat/timelines/callbacks/implicit starts are unverified.                               |
| Paused animate(element, opacity) controls                              | B                                | Native animation was verified paused at the supplied time; not all WAAPI properties/compositor paths.                                                                          |
| Paused animate() spring with fixed initial conditions                  | B                                | Explicit parameters/keyframes/initial velocity and absolute seek; not live spring state.                                                                                       |
| Fresh spring(options).next(timeMs)                                     | A value / B Motion DOM binding   | Fresh evaluator and fixed inputs remove history; retained mutable generators and the full Spring/Retarget API are unverified.                                                  |
| Live useSpring(source)                                                 | C                                | Position/velocity depend on prior animation state; equal targets do not determine equal positions.                                                                             |
| AnimatePresence exit                                                   | C                                | Exit-node retention depends on mounting/traversal history; no absolute-time exit lifecycle in the tested form.                                                                 |
| layout animation                                                       | C                                | Projection requires a previous layout measurement absent on fresh mount; structurally history-dependent.                                                                       |
| Autonomous motion.div animate                                          | C                                | Browser elapsed time, not supplied Presentation Time, progresses the animation.                                                                                                |
| Pure R3F scalar/transform formulas                                     | A values / B rendered expression | Formula uses only supplied time; WebGL still needs integration settlement.                                                                                                     |
| Canvas frameloop="never" + root-local advance(seconds, false)          | B                                | Stopped clock/no independent loop; root-local update excludes global effects. Manual Advance alone does not qualify callbacks.                                                 |
| Camera position + lookAt(0,0,0)                                        | B                                | Absolute orbit/push overwrites pose; damping, automatic fitting, XR and previous-pose interpolation are excluded.                                                              |
| Group rotation/translation                                             | B                                | Overwrite every animated component; deterministic index-derived object positions.                                                                                              |
| Shader uTime assigned from absolute time                               | B                                | Tested procedural shader has no feedback/stochastic history or wall-clock uniform.                                                                                             |
| GPU capture with preserved framebuffer, fixed DPR/size, pinned browser | B                                | Submitted-work settlement and screenshot/readback agreement established in one environment, not cross-backend equality.                                                        |
| Delta-integrating useFrame rotation / accumulated uniform              | C                                | History controls differ; signed deltas, abs(delta) or clamping cannot reconstruct an absolute state.                                                                           |
| Camera updated only at new maximum time / dropping reverse advance     | C                                | Prior maximum or discarded reverse requests leave stale pose/time.                                                                                                             |
| Physics, damping controls, autonomous timers/rAF, temporal feedback    | C / unverified                   | Not implemented by B; hidden state/independent progression cannot be inferred seekable from manual stepping.                                                                   |
| Async models/textures, Suspense, shader/asset readiness                | Unverified by B                  | B has local geometry/synchronous shaders. D verifies finite GLTF/texture cases; the registry plus commit/GPU contract is required, not automatic Tier B for arbitrary loaders. |

No tested Motion DOM path is A. Standard Animate/Reveal/Stagger are not blanket-certified before implementation; a Motion DOM-backed implementation is B. The four Motion negative controls and four R3F history controls are counterexamples, not merely features awaiting wrappers. Public integration APIs, broader behavior coverage and explicit-time replacements remain later-phase work in the ADR's risk handoff.
