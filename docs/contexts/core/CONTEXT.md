# core

The master clock. core defines the Composition, the timeline it runs on, how Sequences and Transitions place scenes in time, and the Time Module that converts between frames and time. It is not responsible for how anything looks.

## Ubiquitous Language

| Term                     | Code                             | Definition                                                                                                                                                               |
| ------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Composition              | `Composition`                    | The root of a video: fps, duration, resolution, and a tree of scenes placed in time.                                                                                     |
| Global Frame             | `globalFrame`                    | The integer index of an output frame, counted from 0 over the whole Composition.                                                                                         |
| Timeline Time            | `TimelineTime`                   | A time on the Composition timeline, kept as an exact rational value until the Time Module converts it.                                                                   |
| Local Time               | `sequenceLocalTime`              | Time relative to the start of a Sequence, returned as exact rational seconds in a `TimelineTime`.                                                                        |
| Presentation Time        | `presentationTime`               | The timeline time at which an output frame is sampled.                                                                                                                   |
| Frame generation         | `FrameSnapshot.generation`       | The monotonically increasing per-realm request identity shared by React, asset and integration acknowledgements, distinct even for repeated requests for the same frame. |
| Frame Rate               | `FrameRate`                      | A positive rational number of frames per second; boundary input uses safe integer `numerator` and `denominator`.                                                         |
| Sequence Interval        | `SequenceInterval`               | Exact start and exclusive end times for a Sequence; zero duration is permitted.                                                                                          |
| Transition Series Timing | `TransitionSeriesTiming`         | Exact scene and overlap intervals and the total duration, without scene content or visual effects.                                                                       |
| Transition Sample        | `TransitionSample`               | Whether an overlap is active and its exact, clamped progress at a supplied time.                                                                                         |
| Time Module              | `src/core/timeline`              | The only place that converts seconds, timeline time, and frames, and defines rounding and comparison. Specified in Lean.                                                 |
| Sequence                 | `Sequence`                       | A scene's display period on the timeline, the half-open interval `[start, end)`.                                                                                         |
| Transition               | `Transition`                     | A period in which two adjacent scenes of a `TransitionSeries` are mounted at once and share a progress value.                                                            |
| Seekability Tier         | `seekability: 'A' \| 'B' \| 'C'` | How far a component's output at a time is independent of the frames rendered before: A guaranteed, B controlled by an integration, C uncontrolled.                       |
| Asset Readiness          | `useAsset`                       | Whether every asset a frame needs (font, image, video frame, model, texture) is loaded, reported before capture; a failure is a diagnostic, not a silent skip.           |

The registry, provider and realm-local coordinator implement TASK-154. Browser loading and transport remain TASK-157.

## Invariants

- Within the supported A/B paths and a fixed environment, a frame is a pure function of its Presentation Time: rendering frame N gives the same output whatever frame was rendered before. Tier C remains usable, not covered by this guarantee; in Phase 1 the Browser Renderer emits `seek.uncontrolled` when an integration is identified as Tier C.
- A Sequence contains time `t` exactly when `start <= t < end` (`Sequence.membership`, `Sequence.start_included`, `Sequence.end_excluded`). Intervals whose endpoints meet, `[a, b)` and `[b, c)`, share no time (`Sequence.adjacent_disjoint`); this does not prohibit overlapping TransitionSeries scenes. Zero-length Sequences are empty (`Sequence.zero_length`). `createSequence` accepts signed starts and nonnegative durations. Local time is the signed exact difference from the start, even outside membership; nested offsets compose without rounding (`Sequence.local_time_zero`, `Sequence.local_time_composition`).
- Frame boundaries are not rounded to integers before the Time Module converts them; fps may be rational (30000/1001). `createTimelineTime` accepts exact `{ numerator, denominator }` input with safe integer components and positive denominator, or finite number seconds within the safe numeric range. Number seconds mean the decimal printed by `String(value)`, not the underlying binary fraction; use rational input when exactness is required. Internally, normalized bigint components preserve arbitrarily large intermediate products. `toSeconds` is a lossy expression-library boundary (including numeric overflow/underflow), never a comparison or rounding input.
- Signed mathematical conversions are unrestricted: `frameToTime(n, fps) = n / fps`, and `framePosition(t, fps) = t * fps`. `timeToFrameFloor` is the default presentation-time-to-frame conversion; an exact frame boundary belongs to that frame. It is monotonic for positive fps and round-trips every signed frame (`Timeline.floor_monotonic`, `Timeline.frame_roundtrip`, `Timeline.floor_bounds`). `timeToFrameCeil` and `timeToFrameNearest` are explicit helpers only; nearest breaks half-frame ties toward positive infinity, including negative ties (`Timeline.ceil_bounds`, `Timeline.nearest_bounds`, `Timeline.nearest_tie`).
- `frameCount(duration, fps)` accepts nonnegative durations and returns `ceil(duration * fps)`; `durationFromFrameCount(count, fps)` reports the exact inverse `count / fps`. That reported duration can exceed the originally requested duration, but counting it returns the same count (`Timeline.frame_count_roundtrip`). Zero duration has zero frames (`Timeline.frame_count_zero`). The last sample is before the requested end; the next sample is at or after it (`Timeline.sampling_bounds`).
- `validateOutputFrame(frame, total)` validates output requests separately from signed mathematical conversion: a safe integer number in `[0, total)` returns `Result<bigint>` success; invalid, negative or out-of-range requests return an error Diagnostic with code `composition.props-invalid`, never clamp or throw (`Timeline.last_frame`, `Timeline.frame_past_end`, `Timeline.negative_frame`). Rejected safe-integer frames appear in `location.frame`; malformed numeric inputs omit location because the Diagnostic schema cannot represent them, and name the received value in the message. Invalid rational/seconds/fps input uses the same code; negative durations/counts and invalid overlap layouts use `composition.duration-invalid` through `Result`.
- `createTransitionSeries` requires exactly one overlap per adjacent scene pair and nonnegative scene durations. Each overlap satisfies `0 <= overlap <= min(left duration, right duration)`; equality is permitted (`Transition.overlap_bounds`). An overlap equal to the outgoing duration starts the incoming scene at zero relative to the outgoing start and leaves the pair with exactly the incoming duration (`Transition.overlap_equal_scene`, `Transition.full_overlap_duration`). At any index and layout offset, incoming scenes start at outgoing end minus overlap (`Transition.layout_adjacent`); both layout-placed scenes are present throughout that half-open overlap (`Transition.layout_overlap_membership`). Zero overlap is empty (`Transition.zero_overlap`). Pairwise constraints do not prohibit multiple simultaneous overlaps in a longer series.
- The total duration of a `TransitionSeries` is the sum of its scenes minus the sum of its overlaps; accumulated placement satisfies this formula (`Transition.placement_total`). Layout entry `i` starts at the initial offset plus the sum of durations before `i` minus the sum of overlaps before `i`, and ends one scene duration later (`Transition.layout_entry`). For durations `[10, 10, 10]`, overlaps `[2, 3]`, and initial offset zero, the placed intervals are `[0, 10)`, `[8, 18)`, `[15, 25)` (`Transition.layout_three_scenes`). An empty series has zero duration and no intervals (`Transition.empty_series`, `Transition.layout_empty`). `sampleTransition` clamps progress before the overlap to 0 and at or after its end to 1 (`Transition.progress_before`, `Transition.progress_after`). Positive overlaps start at 0 (`Transition.progress_start`) and reach 1 at the exclusive end (`Transition.progress_end`). Zero overlaps are never active and switch directly to 1 at their start (`Transition.zero_overlap`, `Transition.progress_end`).
- A component that cannot be identified is never assumed to be Tier A or B.
- The [Composition registry contract](adr/20261024-composition-registry.accepted.md) uses schema-owned defaults, not a parallel `defaultProps`; only validated JSON props mount the selected component. Components and schemas remain in the composition realm.
- The [loading design](../render/design-doc/20261024-composition-loading.md) shares core's browser bootstrap and Composition runtime implementation between preview and renderer, never their sessions, host scheduling or mutable Composition realms.
- core's contract provides one Composition runtime implementation for the Browser Renderer and the future preview to consume; it does not assert that a preview exists. Presentation Time stays fixed while registered work settles. Completion belongs to the active frame generation and resource versions, not just a frame number; allocating a queued generation does not invalidate the active one. Resource-version changes re-settle within that generation; cancellation or supersession aborts it without publication. The [readiness barrier contract](../../decisions/20261024-time-control-and-frame-capture.accepted.md#readiness-barrier-contract) defines exclusive ownership, queueing and deadlines.

## Composition API and host integration

- `defineComposition` returns `Result<CompositionDefinition<Schema>>`; `defineCompositions` accepts the heterogeneous tuple of these Results and returns `Result<CompositionRegistry>`. An entry exports that result as `compositions`. Branch on `ok` before using the registry; declaration failures do not escape module evaluation as exceptions.
- `registry.listCompositions()` returns ordered, frozen plain descriptors without mounting or parsing props. `validateDefaults(revision)` caches successful validation of every entry for that revision and shares in-flight checks; failed/expired checks are evicted for retry. `mount({ compositionId, props, revision })` selects exactly one entry, awaits defaults and parses the raw props once, returning a page-local `PreparedComposition`. Its schema and component never cross transport.
- `<Composition definition={prepared} compositionRuntime={runtime} />` supplies only the selected component's validated props. Create its runtime with `createCompositionRuntime({ definition: prepared, compositionRealm, instance })`; `instance` must be fresh for each realm. No user content renders until ownership supplies a snapshot. `useCompositionFrame()` reads that explicit snapshot; nested Composition roots are rejected rather than treated as Sequences.
- Required nested Suspense content uses a `registerContent(id, version)` handle created **outside** the suspending subtree and a `CompositionContent` inside the content branch, never its fallback. Layout-effect acknowledgements capture both generation and version. A stale or disposed handle cannot acknowledge its replacement.
- `settleFrame` returns `ready`, `failed` or `aborted`. A ready lease retains ownership. `validateCapture` and `completeCapture` reject stale/source-mismatched/duplicate claims; changed registrations return `resettle`. Call `resettle(lease)` without requesting a new generation. Only `completeCapture` returning `accepted` permits publication. Preview presentation uses this core completion operation without making a screenshot claim in transport.
- Queue and frame budgets default independently to 30 seconds. The frame timer begins after `acquire` confirms the host grant, never in the queue, and is not reset by readiness or re-settlement. `acquire` receives an AbortSignal for grant revocation. The host must independently enforce its deadline starting at confirmed grant, including capture RPCs. Local timers cannot interrupt blocked JavaScript/GPU work.
- Cancellation immediately invalidates the generation. The coordinator waits for registered integration callbacks and optional host `quiesce` before granting another request. A callback that never finishes poisons reuse; TASK-157 must recycle that realm. Integrations receive fixed-time snapshots and AbortSignals, not renderer/library objects.
- `dispose()` attempts every integration disposer and clears registrations/listeners even if a disposer throws. It returns a `Result<undefined>` with a sanitized `render.page-error` on disposal failure; repeated calls return the same result without running disposers again. Hosts must check this result when tearing down a realm.
- Prepared props and rendering use the same checked JSON-valued schema output. Non-index array properties are rejected rather than lost in JSON validation's clone.
- Defaults and props each receive a fresh configurable 30-second loading timeout. Schema failure and non-JSON output use `composition.props-invalid`; custom messages/input/params are omitted from sanitized issues. Thrown callbacks/loading expiry and invalid width/height/FPS use `render.page-error`; invalid duration uses `composition.duration-invalid`. Invalid output-frame requests are mapped to `render.page-error` at this runtime boundary, leaving the Time Module's existing standalone mapping unchanged.
- React and ReactDOM are host peers at `^19.0.0`; dev versions remain pinned for tests. The implementation uses React 19-compatible APIs, and the tsconfig requires no narrower runtime range. No React implementation is bundled into this source-distributed package.

`registry.test.ts`, `composition-runtime.test.ts`, and the minimal Chromium `composition.browser.test.tsx` cover the TASK-154 matrix. Asset acquisition/inventory and GPU integration remain TASK-158 and later adapters; full capture and host termination qualification remains TASK-157/158. The public root's resolved browser graph is checked in `scripts/check-browser-graph.test.ts`; TASK-157 must add its browser subpath and emitted entry to that assertion.

## Seekability

The [accepted Phase 0 ADR](../../decisions/20261024-time-control-and-frame-capture.accepted.md) defines the clock and readiness contract. These classifications are scoped to [Spike A](../motion/knowledge/spike-a-seekability.md) and [Spike B](../three/knowledge/spike-b-seekability.md), not guarantees for whole libraries. A is stateless value evaluation; B needs the verified adapter and acknowledgement; C has uncontrolled time/history. Unverified means no A/B claim, not a fourth Tier; unknown integrations receive C treatment until qualified.

| Feature / examined use                                                 | Tier                             | Reason and boundary                                                                                                                                                            |
| ---------------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| External MotionValue bound to motion.div x                             | B                                | Absolute value writes, no velocity/history dependence or live animation; await per-frame postRender.                                                                           |
| Numeric motion.div style.x props                                       | B                                | React flushSync leaves queued Motion work; postRender is required.                                                                                                             |
| Paused animate(MotionValue, [0,160]) controls                          | B                                | Explicit keyframes, autoplay disabled, pause and absolute time assignment; play/speed/repeat/timelines/callbacks/implicit starts are unverified.                               |
| Paused animate(element, opacity) controls                              | B                                | Native animation was verified paused at the supplied time; not all WAAPI properties/compositor paths.                                                                          |
| Paused animate() spring with fixed initial conditions                  | B                                | Explicit parameters/keyframes/initial velocity and absolute seek; not live spring state.                                                                                       |
| Fresh spring(options).next(timeMs)                                     | A value / B Motion DOM binding   | Fresh evaluator and fixed inputs remove history; retained mutable generators and the full Spring/Retarget API are unverified.                                                  |
| Live useSpring(source)                                                 | C                                | Position/velocity depend on prior animation state; equal targets do not determine equal positions.                                                                             |
| AnimatePresence exit                                                   | C                                | Exit-node retention depends on mounting/traversal history; no absolute-time exit lifecycle in the tested form.                                                                 |
| layout animation                                                       | C                                | Projection requires a previous layout measurement absent on fresh mount; structurally history-dependent.                                                                       |
| Autonomous motion.div animate                                          | C                                | Browser elapsed time, not supplied Presentation Time, progresses the animation.                                                                                                |
| Pure R3F scalar/transform formulas                                     | A values / B rendered expression | Formula uses only supplied time; WebGL still needs integration settlement.                                                                                                     |
| Canvas frameloop="never" + root-local advance(seconds, false)          | B                                | Stopped clock/no independent loop; root-local update excludes global effects. Manual Advance alone does not qualify callbacks.                                                 |
| Camera position + lookAt(0,0,0)                                        | B                                | Absolute orbit/push overwrites pose; damping, automatic fitting, XR and previous-pose interpolation are excluded.                                                              |
| Group rotation/translation                                             | B                                | Overwrite every animated component; deterministic index-derived object positions.                                                                                              |
| Shader uTime assigned from absolute time                               | B                                | Tested procedural shader has no feedback/stochastic history or wall-clock uniform.                                                                                             |
| GPU capture with preserved framebuffer, fixed DPR/size, pinned browser | B                                | Submitted-work settlement and screenshot/readback agreement established in one environment, not cross-backend equality.                                                        |
| Delta-integrating useFrame rotation / accumulated uniform              | C                                | History controls differ; signed deltas, abs(delta) or clamping cannot reconstruct an absolute state.                                                                           |
| Camera updated only at new maximum time / dropping reverse advance     | C                                | Prior maximum or discarded reverse requests leave stale pose/time.                                                                                                             |
| Physics, damping controls, autonomous timers/rAF, temporal feedback    | C / unverified                   | Not implemented by B; hidden state/independent progression cannot be inferred seekable from manual stepping.                                                                   |
| Async models/textures, Suspense, shader/asset readiness                | Unverified by B                  | B has local geometry/synchronous shaders. D verifies finite GLTF/texture cases; the registry plus commit/GPU contract is required, not automatic Tier B for arbitrary loaders. |

No tested Motion DOM path is A. Standard Animate/Reveal/Stagger are not blanket-certified before implementation; a Motion DOM-backed implementation is B. The four Motion negative controls and four R3F history controls are counterexamples, not merely features awaiting wrappers. Public integration APIs, broader behavior coverage and explicit-time replacements remain later-phase work in the ADR's risk handoff.
