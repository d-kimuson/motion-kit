# agent

What a coding agent operates. agent provides the CLI and diagnostics: render, frame and docs today, inspect and validate later, with JSON output so an agent can act on the result without a GUI.

## Ubiquitous Language

| Term              | Code                   | Definition                                                                                                                                                                 |
| ----------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI               | `motion-kit <command>` | The command-line entry; every command supports JSON output.                                                                                                                |
| Docs              | `docs`                 | Printing a guide that ships with the package, or listing the guides. `motion-kit docs [topic]` prints one verbatim; `--list` names all topics.                             |
| Diagnostic        | `Diagnostic`           | A structured finding defined by [`DiagnosticSchema`](../../../src/lib/diagnostic.ts) and the [accepted CLI output contract](adr/20261024-cli-output-contract.accepted.md). |
| Inspect           | `inspect`              | Reporting a Composition's structure, time ranges, assets, seekability tiers, and diagnostics without rendering video.                                                      |
| Validate          | `validate`             | Checking a Composition against schemas and rules and returning diagnostics.                                                                                                |
| Layout Diagnostic | `LayoutDiagnostic`     | A problem found by DOM measurement: overflow, out-of-frame placement, unexpected scroll, unloaded font, missing asset.                                                     |
| Contact Sheet     | `contact-sheet`        | A grid of representative frames for visual review.                                                                                                                         |

## Invariants

- Every failure the CLI reports is a Diagnostic; stack traces are never included in JSON; an internal-failure stack goes to stderr only.
- An invocation the CLI cannot run still emits one envelope under `--json`: `command` names the known subcommand the first positional argument is (`render`/`frame`/`docs` even when written after a flag, `inspect`/`validate` as not implemented yet) or is `null` (never a sentinel member) when argv names none, always with a `cli.invalid-arguments` hint that says what to do next; a reserved subcommand's message says it is not implemented rather than blaming the arguments. Without `--json` it stays a stderr message and exit code 2. A deliberate help request is the one exemption, in exactly two forms: `--help`, `-h` or `help` as the leading token, or `--help`/`-h` among the arguments of a leading `render`/`frame`/`docs`. Those print usage text on stdout and exit 0, with or without `--json`, and emit no envelope; any other argv (`--json --help`, `--json render entry.tsx --help`) gets the envelope.
- Include known location information in each Diagnostic according to the accepted CLI output contract.
- The [accepted CLI output contract](adr/20261024-cli-output-contract.accepted.md) fixes the JSON envelope, severity semantics, exit codes, and versioning policy.

## Cancellation

`motion-kit` binds `SIGINT`, `SIGTERM` and `SIGHUP` to one `AbortController` per invocation (`watchSignals` in `src/cli/cli.ts`, installed by `src/cli/main.js`) and passes its signal to `createRenderer` (`frame`), `createRendererPool` (`render`, which opens `--concurrency` renderers, half the machine's parallelism by default), `renderFrame`, `renderFrames` and `renderVideo`. A cancelled run is aborted control flow, not a result: **no envelope is emitted** — the schema cannot express "stopped", and fabricating a Diagnostic (or `internal.unexpected`) would call the caller's own intent a domain failure or a bug — nothing is written to stdout, one line goes to stderr, and the exit code is `128` plus the signal number: `130` for `SIGINT`, `143` for `SIGTERM`, `129` for `SIGHUP`, the same code a shell reports for a process it interrupted. Both `render` routes behave identically: the `.mp4` route kills the FFmpeg child (`SIGTERM`, then `SIGKILL`), removes the temporary sibling and leaves no target, and the frames route stops before writing `manifest.json`, so a partial sequence is never claimed complete (the PNGs already written stay). A second signal does not wait for that cleanup: it performs the same synchronous work an exit performs (see below) and leaves at once with `128` plus the second signal's number, so a second `Ctrl-C` ends the process immediately and still leaves no temporary sibling and no child behind. That line is owed only while the run can still be stopped before it commits: a route reports its outcome as decided the moment the artifact is on disk (or the failure is final) and releases the line there, before it tears the renderer down, because that teardown outlasts the render (a page-dispose deadline, the service-dispose race, a browser kill) and a stop inside it would describe a complete `out.mp4`, or a frames directory with its `manifest.json`, as never produced. One signal in that window leaves the finished run to exit `0` with its envelope; a second one still ends the process at once, leaving the committed artifact and no claim to the contrary.

That contract is the CLI's, so nothing else in the process may end a run early. Playwright installs its own `SIGINT`/`SIGTERM`/`SIGHUP` handlers when it launches a browser (`addProcessHandlerIfNeeded` in `playwright-core`): the `SIGINT` one exits `130` as soon as its browsers close, inside the same signal dispatch, ahead of the asynchronous cleanup that has to kill the encoder, remove its temporary sibling and write the line, while the `SIGTERM` and `SIGHUP` ones only close the browsers — which would turn a supervisor stop or a closed terminal into a mid-render browser failure instead of the caller's cancellation. The launcher therefore disables all three (`handleSIGINT`, `handleSIGTERM`, `handleSIGHUP` are `false` in `chromiumOptions`, `src/render/browser/launch.ts`) and the CLI watches them itself; Playwright's `exit` handler still kills the processes it tracks. Because no guarantee may depend on which listeners another library happens to install, the work a cancelled run promises is _also_ registered as a synchronous cover on `process.on('exit')` (`coverOnExit` in `src/lib/exit.ts`): the FFmpeg child is killed, its temporary sibling removed, the loading service's process group killed and the one line written. A cover runs once, synchronously, and cannot await. Every exit that reaches that listener — a normal return, another library's handler calling `process.exit`, the CLI's own second-signal path — therefore leaves exactly the state a cancellation leaves. A signal the process never observes runs no listener at all: `SIGKILL`, a fatal fault and a termination that re-raises a signal leave whatever the run had written so far, which is the one exit this guarantee cannot reach.

## render output format

`render --out <path>` selects the format from the target's extension: an `.mp4` file is encoded H.264 video and reports `data.format: "mp4"`, and any other target is a PNG frame sequence in that directory reporting `data.format: "frames"` with a `manifest`. There is no `--format` flag; the format is envelope data fixed by the CLI output contract, not an argument, so the target path is the only place it can come from. The `.mp4` route needs a working FFmpeg 6.0+ with `libx264` on `PATH` ([system FFmpeg ADR](../render/adr/20261025-system-ffmpeg-encoder.accepted.md)), probed once per invocation before the first frame: a missing or unsupported binary is `encode.ffmpeg-not-found` or `encode.ffmpeg-unsupported`, a failure the agent resolves by installing FFmpeg rather than by changing the Composition. Both routes report the warnings capture emitted per frame — `seek.uncontrolled` for a detected Tier C Composition, `layout.*` for measured layout problems — in the envelope's `diagnostics`, so a successful render is `ok: true` with warnings, never `ok: true` with an empty array. **Audio has no flag either**: the `.mp4` route muxes whatever the Composition declares in `audio` ([audio muxing ADR](../render/adr/20261026-audio-track-muxing.accepted.md)), resolving its `src` against the invocation's project root, so a missing file is `asset.load-failed` with the file in `location` and no output, and a Composition that declares none is the unchanged silent render.
