# Commit only CC0 and OFL example assets, and generate or fetch the rest locally

## Context

Status: **accepted**. The reference examples fixed by TASK-168 (the reference-examples design doc, not written yet) bring third-party works into a public MIT repository: Japanese narration by Zundamon (ずんだもん) and Shikoku Metan (四国めたん) through VOICEVOX, their character sprites, and a Japanese font. The background music and the photos for the slideshow are not among them — those are the project's own FFmpeg output, with no terms to honour. The voices, the sprites and the font each carry terms that are not MIT, and a committed file is redistributed by every clone and fork. The rule has to exist before the first asset lands, and it has to be written once.

`scripts/check-licenses.ts` reviews **npm production dependencies** only (`pnpm licenses list --prod`), and `REVIEW.md` (Dependencies) reviews non-package tooling such as the FFmpeg binary by hand. An asset is neither: no check reads it, so this ADR is its review.

The forces:

- MIT covers what the project authors own. A second licence cannot be claimed over a file whose holder did not grant it, and MIT cannot carry a condition such as "credit me".
- The characters belong to the 東北ずん子・ずんだもんプロジェクト (SSS LLC.); VOICEVOX only synthesizes speech. The voice terms and the illustration terms are separate documents with different permissions, and the sprites have their own illustrators.
- CI must render its clips without network access and without a voice engine, and a clone must stay small.
- The narrated benchmark video (LOCAL-1, the owner's request of 2026-10-25: the explainer render recorded with Japanese narration over it) must be producible on the author's machine now, where no VOICEVOX engine is installed.

## Decision

A committed asset must satisfy two things at once: its terms permit verbatim redistribution, and any condition it imposes is discharged by the file itself rather than by behaviour the repository cannot control downstream. CC0 (no condition) and the OFL (its condition is the shipped licence text) pass. A credit obligation on the recipient, or a prohibition on re-sublicensing, does not. Everything that fails is generated or fetched into an ignored directory and never committed.

| Asset                                               | Committed?                        | Terms                                  | Produced by                                                                              | Credit                                          |
| --------------------------------------------------- | --------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Japanese font (Noto Sans JP)                        | Yes — `.woff2` + `OFL.txt`        | OFL-1.1                                | Fetched once from `ofl/notosansjp`, converted to one `.woff2` (command below), committed | None required; the OFL text ships with it       |

| Local narration (`say -v Kyoko`)                    | No                                | Apple SLA §F                           | Local command → ignored directory, local renders only                                    | Not applicable (never published)                |

The allowlist for a committed file under `examples/` is therefore: CC0-1.0, and OFL-1.1 for fonts. The other licences `scripts/check-licenses.ts` allows stay package-only; this ADR neither widens nor narrows them. An OFL font must not arrive as an npm dependency (the check would fail, because `OFL-1.1` is not in its allowlist); it arrives as a file with its `OFL.txt` beside it. If a font package ever becomes unavoidable, it is added to that script's `EXCEPTIONS` with the reason, and `OFL-1.1` is not added to `ALLOWED`, which governs what the library itself ships.

Fonts are the one Japanese-specific exception. The example uses **Noto Sans JP** (variable weight, the widest kana and kanji coverage, OFL with Reserved Font Name 'Source'); BIZ UDPGothic is the alternative when a UD face is preferred. The macOS system Japanese fonts are never used: §E of the Apple licence permits embedding only where the font's own restrictions allow, and nothing grants redistribution, so the rendered frame would also differ per machine.

The committed file is a `.woff2`, and `ofl/notosansjp` does not ship one: it publishes the variable `NotoSansJP[wght].ttf` (9,589,900 bytes) beside `OFL.txt`. Convert it once, commit the result beside the licence, and record the command in the example's README:

```sh
curl -O 'https://raw.githubusercontent.com/google/fonts/main/ofl/notosansjp/NotoSansJP%5Bwght%5D.ttf'
curl -O 'https://raw.githubusercontent.com/google/fonts/main/ofl/notosansjp/OFL.txt'
npx --yes --package wawoff2 woff2_compress.js 'NotoSansJP[wght].ttf'   # → NotoSansJP[wght].woff2, 4,350,136 bytes
```

Both sizes are recorded because the gap between them is what the repository would carry: the 4.3 MB `.woff2` is what gets committed, and a change that quietly commits the 9.6 MB `.ttf` instead shows up in review. `pyftsubset --flavor=woff2` (the `fonttools` package) is the equivalent conversion and can subset to a text range in the same step, which is how to shrink the file further if 4.3 MB ever matters — at the price of deciding, up front, which kanji the example can render.

Do not fetch the `.woff2` from the `css2` API instead. `https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400` answers with 124 `@font-face` blocks, one per `unicode-range` subset, pointing at 124 files on `fonts.gstatic.com`: committing that is committing 124 files whose coverage is decided by Google's ranges rather than by the example's text, and the CSS changes when Google regenerates the subsets. One variable `.woff2` from the upstream TTF covers every kanji and keeps the weight axis.

TASK-168 fixes the asset layout; this decision only requires that the tree distinguishes a committed asset directory from an ignored local one (`assets/` and `assets.local/` unless TASK-168 names otherwise), and that the generation and fetch scripts are committed. The ignore rule itself is already in `.gitignore` from this decision, so the local-only rule does not rest on memory between now and the first example.

音声: VOICEVOX:ずんだもん / VOICEVOX:四国めたん

The voice terms require the credit where a viewer who looks for it finds it, and the sprite guideline requires no copyright notice but does require the character to stay recognisable; naming the illustrator is the courtesy this repository keeps. TASK-170 includes the block in that README.

### Local narration on a machine without VOICEVOX

macOS `say` is the accepted local stand-in: `say -v Kyoko -o line.aiff "<text>"`, converted with the FFmpeg the render pipeline already requires. Its output is a **local-only** artifact. §F of the Apple licence allows the System Voices for personal, non-commercial content only and forbids recording, publishing or redistributing them in any public-sharing context, so the generated file is never committed, never attached to a PR, issue, Slack message or published artifact, and a video narrated with it stays on the machine that made it. A video that may be published must use VOICEVOX output and show the credit.

The VOICEVOX path needs no repository change: run the engine locally (`docker run --rm -p 127.0.0.1:50021:50021 voicevox/voicevox_engine:cpu-latest`, or the release binary) and let the example's generation script call `/audio_query` and `/synthesis`. The engine is never vendored, because a clone must stay small and the examples reach it over HTTP from outside the tree — not because its licence forbids it: LGPL-3.0 is a redistribution grant, and it is why the engine ships as source, as releases and as the image above. The prohibition on redistributing the software quoted in the table is the VOICEVOX ソフトウェア利用規約's, which governs the VOICEVOX application; the engine's own terms are LGPL-3.0 or a separate licence, and neither is the repository's to pass on, because it ships no engine. Neither route is ready on the author's machine today — no engine is installed and the Docker daemon there did not answer — so publishing a narrated video starts with installing one, and TASK-170's setup section says which.

The narrated benchmark video this decision has to serve is LOCAL-1, the owner's request of 2026-10-25: the explainer render recorded with Japanese narration over it, to show the pipeline end to end. The owner decided with that request that it stays **local-only for now** — not published, not committed, and not attached to a pull request, issue or Slack message — so `say` is the right tool for it and no engine has to be installed before it can be produced. Publishing it later, by linking it from the README or reporting it to the team, is a separate decision that needs the VOICEVOX engine above and a re-recording with its output; the §F restriction is why the `say` narration cannot be reused for that.

### Open to the owner

- The sprite sets have no stable direct download URL (the authors distribute through ニコニコ静画 and BOOTH with the link in the description), so a setup script may need a manual download step. Accepting that, choosing another set, or shipping silhouette placeholders is the owner's call.

## Consequences

`examples/` keeps one licence for the bytes it commits, so no carve-out in `LICENSE` is needed and `scripts/check-licenses.ts` keeps its package-only scope. Each example gains a setup script and a README section that says which assets are downloaded or generated and where they land; a render started before setup fails through the existing `asset.load-failed` diagnostic of the [asset readiness ADR](20261023-asset-readiness-registry.accepted.md) rather than rendering a silent fallback. CI renders only clips built from committed fonts and generated placeholders, so it needs neither network nor an engine; full renders with voices and sprites stay a local QA Check, as TASK-168's CI policy requires. The cost is that a fresh clone cannot render the explainer until the script runs, and that the repository holds no ready-made narrated video.

## Alternatives

- **Commit the VOICEVOX audio with the credit:** legal — 許諾内容 3 of the [VOICEVOX ソフトウェア利用規約](https://voicevox.hiroshiba.jp/term/) allows granting others the use of generated audio provided they are bound to 許諾内容 2 and 3, whose credit and common rules the [音源利用ガイドライン](https://zunko.jp/con_ongen_kiyaku.html) supplies. Rejected because that obligation cannot travel with an MIT file once it is copied out of the repository, and the script reproduces the audio from the script text in seconds.
- **Commit the sprites:** the project guideline prohibits re-sublicensing the granted licence (item 10), so an MIT grant over the sprite is not the project's to make.
- **Use the official character illustrations instead of a third-party sprite set:** also non-commercial only and also not re-sublicensable, and they carry fewer expressions than the sprite sets the explainer needs.
- **Commit Pixabay or Unsplash photos and tracks:** Pixabay forbids distributing content on a standalone basis, which a repository file is; Unsplash adds conditions (no selling unmodified images, no competing compilation) that MIT would contradict.
- **Use the macOS system Japanese font:** no redistribution right and an embedding restriction, and the same composition would render differently on another machine.
- **Decide this after the examples design doc:** TASK-170 needs the credit lines now, and committed assets are hard to withdraw once published.
