# Lean Spec

Deterministic rules are written as Lean 4 specifications next to the implementation. The Lean file is the specification: the doc comments explain the rules, the theorems prove the properties, and a differential test checks that the TypeScript implementation agrees with it.

## Scope

- The Time Module in `src/core`: conversion between seconds, timeline time, and frames with rational fps, rounding and comparison rules; Sequence `[start, end)` membership and composition; Transition overlap and total duration.
- Not: spring and easing evaluation (floating point, checked with property-based tests), React components, anything that touches the browser.

## Placement

```text
src/core/timeline/
├── clamp-frame.lean            # the spec: definitions, constraints, theorems
├── clamp-frame.lean.md         # generated by `node scripts/lean-spec.ts doc src/core`; committed
├── clamp-frame.ts              # the implementation
└── clamp-frame.oracle.test.ts  # the differential test
spec/
├── Oracle.lean                 # the oracle: dispatches a JSON request to a spec function
└── oracle.ts                   # runs .lake/build/bin/spec-oracle from a test
```

`lakefile.toml` builds every `.lean` under `src/core` (`globs`) and the `spec-oracle` executable. The build output `.lake/` is gitignored.

## Writing a spec

- One file per rule set, `namespace` matching the module (`Timeline`, `Sequence`, `Transition`). Definitions are total functions over Lean types (`Nat`, `Rat`, structures), never `Float`.
- Every `def` and `theorem` has a doc comment (`/-- ... -/`) that states the rule or the claim in English. The theorem's doc says what holds, not how it is proved.
- Each rule from `docs/tmp/design.md` or a `CONTEXT.md` invariant becomes a theorem; each boundary (exact threshold, zero, empty, upper bound) becomes a theorem too.
- Constraints on inputs (`total ≥ 1`) are hypotheses of the theorems that need them; the differential test's generators respect the same constraints.
- Register the function in `spec/Oracle.lean` (`import` the module, add a `match` case that reads `args` and returns `toJson`). A structure argument derives `FromJson`/`ToJson`.
- `node scripts/lean-spec.ts check src/core` fails when a declaration lacks a doc comment or the `.lean.md` is stale; regenerate with `node scripts/lean-spec.ts doc src/core` and commit both.

## Build and check

- `lake build` checks the proofs and builds `.lake/build/bin/spec-oracle`. Run it after changing any `.lean` file and before `pnpm test`; CI runs it with `leanprover/lean-action`.
- Ask the oracle by hand: `echo '{"fn":"Timeline.clampFrame","args":{"total":10,"frame":12}}' | .lake/build/bin/spec-oracle` prints `9`; an unknown function prints `{"error":"unknown function: ..."}`.

## Differential test

- The implementation is written from the spec by hand (TypeScript `number`, not Lean types); the differential test is what ties them together.
- Generators follow the Lean types and the theorems' hypotheses: `Nat` becomes a non-negative integer, a hypothesis `total ≥ 1` becomes `min: 1`.
- Aim generators at the boundaries the theorems name (the last frame, the frame past the end, zero, an empty interval); uniform random inputs rarely hit them.
- Compare the whole result with `toEqual`; convert between JSON and TypeScript values only inside the test, never inside the implementation.
- A failure prints the counterexample and both values. Reproduce it by `docs/guidelines/quality-assurance/index.md` (Reproducing a failure).
- The test needs the oracle binary; `spec/oracle.ts` throws with instructions when `.lake/build/bin/spec-oracle` is missing.

The differential test uses fast-check and vitest, is named `<name>.oracle.test.ts` next to the implementation, and calls the oracle through `spec/oracle.ts`:

```ts
import fc from 'fast-check';
import { describe, expect, it } from 'vitest';

import { evalSpec } from '../../../spec/oracle.ts';
import { clampFrame } from './clamp-frame.ts';

// Inputs follow the Lean types: `total` and `frame` are Nat; `total` is at least 1 (clampFrame_lt's hypothesis).
// Frames around the end of the timeline (total - 1, total, total + 1) are the boundary the spec is about.
const inputs = fc
  .record({
    total: fc.integer({ min: 1, max: 100_000 }),
    offset: fc.integer({ min: -1, max: 1 }),
    frame: fc.nat(200_000),
  })
  .chain(({ total, offset, frame }) =>
    fc.constantFrom({ total, frame }, { total, frame: Math.max(total + offset, 0) }),
  );

describe('Timeline.clampFrame', () => {
  it('matches the spec', () => {
    fc.assert(
      fc.property(inputs, ({ total, frame }) => {
        expect(clampFrame(total, frame)).toEqual(evalSpec('Timeline.clampFrame', { total, frame }));
      }),
    );
  });
});
```
